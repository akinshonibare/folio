## Known data-quality / accuracy notes

- **OCC option symbol format**: 6-char underlying (right-padded with spaces), 6-char date `YYMMDD`, 1-char type `C`/`P`, 8-char strike (price × 1000, zero-padded). The parser is in `src/lib/options/occ.ts`. Adjusted options (after corporate actions) may have non-standard strikes — parse what's there and let the user verify; don't try to round them.
- **Wealthsimple's `Name` column is blank for options** in the holdings export. We synthesise a display name from the parsed underlying + strike + expiry.
- **Crypto rows have no `Exchange` / `MIC`**. Match them by `Security Type = CRYPTOCURRENCY` and route to CoinGecko for quotes (Phase 3).
- **CDRs** (CAD-hedged Canadian-listed depositary receipts of US stocks, e.g. `GOOG.NE`, `UNH.TO`): live quote currency must match the snapshot currency before overlay, or USD prices on CAD-listed CDRs inflate the portfolio ~5×. Carry forward the `live currency must equal stored currency` guard from invest-manage (see invest-manage TODO #3).

## Don't regress

1. **Every table that holds user data has `user_id text not null`** (Clerk subject), and every query filters by `user_id`. Demo mode (when added) reads fixtures, never the DB. Same invariant as invest-manage TODO #13a.
2. **Snapshots are immutable.** A CSV upload creates a new `snapshots` row; nothing edits an existing one. Movement calc is `current_snapshot - previous_snapshot` keyed on `(user_id, account_id, instrument_id)`.
3. **Option instruments key on `(occ_symbol)`**, NOT on the underlying. Two different strikes/expiries of the same underlying are distinct instruments. The unique constraint on `instruments` for options is `(occ_symbol)`.
4. **Quote provider preference is per-user**, stored in `user_settings.quote_provider` (`yahoo` | `polygon`). If `POLYGON_API_KEY` is unset, the provider resolver falls back to Yahoo regardless of preference and the UI toggle is hidden.
5. **Stealth mode wraps every dollar render** via a `<Cash>` component or `useCash()` hook. When you add new $ values to the UI, route them through this — otherwise the friend-group masking won't catch them.
6. **`drizzle-kit migrate`, not `push --force`.** We're multi-user from day 1, so schema changes go through generated migrations (`pnpm db:generate` → review SQL → `pnpm db:migrate`). The opposite policy of invest-manage, on purpose.
